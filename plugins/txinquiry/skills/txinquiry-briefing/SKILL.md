# TX Inquiry 상담 현황 브리핑

상담원·팀장이 화면 여러 개를 돌지 않고 지금 상태를 한 번에 파악하도록, 여러 조회를 모아
**우선순위 순으로** 보고한다.

## 수집

| 항목 | 도구 |
|---|---|
| 내 계정·권한 컨텍스트 | `whoami` |
| 내 담당 문의 건수 | `get_my_inquiry_counts` |
| 전체 문의 상태별 건수 | `get_inquiry_counts` |
| 실시간 대기열 | `list_wait_queue_active`, `get_wait_queue_status` |
| 오늘 상담원 로스터 | `list_agent_roster` |
| 우선배정 설정 | `list_priority_assigns` |
| 내 소속 팀 | `get_my_teams` |

## 보고 형식

1. **지금 조치 필요** — 대기열에 쌓인 고객, 미배정 문의, 오래 답변이 없는 건.
2. **오늘 처리할 일** — 내 담당 문의를 상태별로. 각 항목에 건수와 다음 액션 한 줄.
3. **참고 현황** — 팀 전체 건수, 로스터·우선배정 설정.

- 0건 항목은 생략한다. 전부 0이면 "처리할 일 없음"을 분명히 말한다.
- 조회 하나가 실패해도 나머지는 보고하고, 실패한 항목은 **"확인 불가"** 로 표시한다. 0건으로 바꾸지 않는다.
- 사용자가 "그거 보여줘/처리해줘"라고 하면 `txinquiry-triage` 또는 `txinquiry-handling` 절차로 넘어간다.
  브리핑 안에서 바로 쓰기 도구를 호출하지 않는다.

## 조회 기준

- 이 서버의 목록·집계 도구는 **기간 기본값을 서버가 정해 주지 않는다.** 사용자가 기간을 말하지 않으면
  기간을 먼저 제시하고(예: 오늘 / 최근 7일), **답변에 사용한 기간과 기준을 반드시 밝힌다.**
- 로스터·일자 기준 도구는 조회 일자를 명시해야 한다. "오늘"이 어느 날짜인지 답변에 적는다.
- 화면 숫자와 다르면 기간·상태 필터·담당자 범위(내 것 / 팀 전체)부터 대조한다.
