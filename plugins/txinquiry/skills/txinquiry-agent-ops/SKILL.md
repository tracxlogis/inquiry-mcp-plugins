# TX Inquiry 상담원 운영·정책

팀장·관리자가 **상담 인력과 배정 정책을 확인하고 조정하는** 업무다. 상담원 개인 티켓 처리는
`txinquiry-triage` / `txinquiry-handling` 을 쓴다.

## 1. 현황 조회

- `list_agent_roster` — 일자별 상담원 로스터. 조회 일자를 명시한다.
- `list_agent_settings` — 상담원별 설정.
- `list_channel_incharges` — 채널별 담당자.
- `list_priority_assigns` — 우선배정 설정.
- `get_my_teams` — 내 소속 팀 범위 확인.
- `list_spam_policies` — 스팸 정책 목록.
- `explain_inquiry_behavior` — 배정·상태 전이가 왜 그렇게 동작하는지 확인.

## 2. 조정 (쓰기 — 전부 `confirm=true` 필요)

| 하려는 일 | 도구 | 주의 |
|---|---|---|
| 상담원 상태 변경 | `set_agent_status` | **다른 사람의 근무 상태**를 바꾼다. 대상자 이름과 바꿀 상태를 밝히고 동의받는다 |
| 일별 집계 생성 | `build_agent_daily` | 대상 일자를 명시한다. 이미 만든 날짜를 다시 만들면 값이 바뀔 수 있다 |
| 상담 지표 재계산 | `rebuild_agent_cvt` | 집계를 다시 만드는 작업이다. 범위와 소요를 먼저 알린다 |
| 스팸 정책 변경 | `manage_spam_policy` | 정책이 바뀌면 **이후 인입 문의 처리에 전면 영향**을 준다. 무엇을 어떻게 바꾸는지 값 단위로 보고 |

## 3. 확인

변경 후 같은 조회 도구로 재조회해 반영을 확인하고, 영향 범위(대상 인원·적용 시점)를 함께 보고한다.

## 규칙

- 이 스킬의 변경은 **본인이 아닌 다른 사람의 업무 조건**을 바꾼다. 요청자가 그 권한을 가진 사람인지
  확인이 필요하면 실행 전에 되묻는다.
- 권한은 호출 시점에 서버가 판정한다. 거절되면 우회하지 말고 필요한 권한을 안내한다.
- 집계·재계산 도구는 되돌리기 어렵다. 대상 일자·범위를 사용자가 명시적으로 확인한 뒤 실행한다.
- 조회 기간 기본값은 서버가 정해 주지 않는다 — 사용한 일자·범위를 답변에 밝힌다.
